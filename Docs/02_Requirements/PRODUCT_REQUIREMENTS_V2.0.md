# RaceGame 产品需求 V2.0

## 1. 目标

以当前工程、上传原型和成熟虚拟赛马产品常见结构为输入，建立可实现、可测试、可运营的统一业务合同。

## 3. 轮次状态机

```text
Betting(1)
  ├─ 无有效下注 → Finished(6)
  └─ 有下注 → Preparing(3) → Racing(4) → Settlement(5) → Finished(6)

任何阶段的运营取消必须进入 Cancelled(7)，禁止回退。
Closed(2) 为历史协议保留值，不作为 V2.0 正常状态。
```

## 4. 下注规则

- 登录玩家才可下注；
- 只能选择 1 匹马；
- 可以对同一匹马多次追加；
- 不允许换马；
- 金额必须 >= 最低下注；
- 余额必须足够；
- 截止时间以服务端 UTC 为准；
- 每次请求必须带幂等键；
- 幂等键重复且请求参数不同必须返回 `IDEMPOTENCY_REQUEST_MISMATCH`，不能静默返回旧订单；
- 订单锁定赔率，结算不得重新读取当前赔率。

## 5. 赔率与赛果

赔率是“本轮 6 马的历史表现快照 + 版本化算法”的结果；创建轮次时保存快照。赛果使用独立版本、密码学随机盐和 SHA-256 派生种子。比赛开始后只广播动画参数，最终名次由服务端数据库确定。

## 6. 钱包规则

所有余额变化必须在同一事务中完成：

`业务订单 + wallet + wallet_transactions + 业务履约/结算日志`

并且：

- PostgreSQL 行锁保护玩家钱包；
- 唯一幂等键防止重复流水；
- 金额使用 NUMERIC/decimal；
- 不允许负余额；
- 中奖奖励使用下注订单的 LockedOdds；
- 手续费只对获胜订单计算。

## 7. 商城

V2.0 仅支持游戏币商品。商品可发放角色、装扮、道具。商品状态、生效时间、每日/终身限购均由后台控制。客户端不得显示可点击的现金充值或链上充值入口。

## 8. 任务

每日任务至少覆盖：完成比赛、赢得比赛、失败比赛。领奖必须幂等，奖励与钱包流水同事务。

## 9. 排行榜

玩家榜：至少 5 场参与后进入榜单，按胜率→胜场→玩家 ID 稳定排序。

马匹榜：按胜率→胜场→马匹 ID 稳定排序。

客户端不得自行计算最终排名。

## 10. 账号安全

- PBKDF2-SHA256 密码哈希；
- Refresh Token 只存哈希；
- Refresh Token 轮换；
- 修改密码撤销全部会话；
- 登录失败达到阈值后临时锁定；
- 登录提示明确区分：账号不存在时提示“账号不存在，请先注册账号”，密码错误时提示“账号或密码错误”；
- 增加退出登录接口；
- dev-login 只允许 Development/Test 环境；
- 生产环境不返回内部异常详情。

## 11. 原型与业务冲突处理

图片中出现的“现金充值/链上充值/USDT/钱包连接”等展示仅作为视觉参考，不作为当前业务合同。原因是当前产品定义为纯虚拟币游戏；任何真实货币功能都需要重新完成合规、支付、账务、风控、地区策略和平台审核设计。
