> 版本：V1.5

## 1. 本次实施目标

本次将 API、Worker、数据库和 Cocos 简单 UI 串成完整业务闭环，并优先保证：

- 比赛、马匹、角色三类业务日志完全拆表；
- 轮次赛果、赔率、黑马和动画仍由服务端权威生成；
- 玩家角色、等级经验和装备状态可以从 API 读取和修改；
- 马场和下注历史支持服务端分页；
- 公告、角色和后台数据管理 API 补齐；
- 余额归零后生成两小时补偿任务，由 Worker 到期发放；
- 客户端使用简单边框 + 文字 + 点击完成 P0/P1 基础页面；
- 新增/修改代码按项目 Skill 要求添加注释并保持文件职责清晰。

## 2. 数据日志拆分

### 2.1 `race_logs`

只记录比赛级事件，例如：

- `RACE_CREATED`
- `RACE_RESULT_GENERATED`
- `RACE_STARTED`
- `RACE_FINISHED`
- `RACE_SETTLED`
- `RACE_SKIPPED`

JSON 记录本次比赛规则、状态、算法版本、结果摘要等。

### 2.2 `horse_logs`

只记录单匹马事件，例如：

- `HORSE_ENTERED`
- `HORSE_RESULT_GENERATED`
- `HORSE_RESULT_SETTLED`

JSON 记录当轮赔率、历史概率快照、完成时间、名次、黑马信息等。

### 2.3 `character_logs`

只记录玩家角色资产变化，例如：

- `CHARACTER_GRANTED`
- `CHARACTER_EQUIPPED`
- `CHARACTER_RACE_EXP`

JSON 记录来源、等级、经验变化和装备切换信息。

三张日志表不互相混合；当前状态仍由业务主表保存，日志用于历史追溯。

## 3. API 补充

新增：

- `GET /api/characters`
- `PUT /api/player/character`
- `GET /api/player/assets`
- `GET /api/notices/active`
- `GET /api/player/bets/{orderNo}`

增强：

- `GET /api/stable/horses` 支持 `page/pageSize`；
- `GET /api/player/bets` 支持 `status/fromUtc/toUtc`；
- `GET /api/player/me` 返回当前角色和补偿状态；
- `GET /api/race/*` 保持服务端结果隐藏策略。

后台 Web API：

- `GET/POST/PUT /admin/api/characters`
- `GET /admin/api/tasks`
- `GET /admin/api/shop/products`
- `GET /admin/api/players/{id}/races`

## 4. Worker

Worker 除轮次推进外处理到期破产补偿：

- 只处理 `SCHEDULED` 且 `GrantAt <= UTC now` 的任务；
- 每个玩家每个 `Europe/London` 自然日最多成功 5 次；
- 补偿不检查当前余额；
- 发放与钱包流水在同一数据库事务；
- 幂等键保证同一补偿不会重复发放。

## 5. 客户端

当前客户端采用轻量动态 UI：

- 登录/注册；
- 大厅；
- 赛场；
- 结果；
- 每日任务；
- 马场；
- 角色；
- 排行榜；
- 商城；
- 下注记录；
- 公告与规则；
- 设置/修改密码。

UI 不承担赛果、余额、奖励计算，只展示 API/SignalR 返回的数据。

## 9. Cocos Creator 版本固定

- `Client/project.json` 已固定为 `cocos-creator` + `3.8.8`。
- `Client/tsconfig.json` 使用严格 TypeScript 配置，客户端脚本禁止新增 `any`。
- `Client/package.json` 锁定 `@cocos/creator-types` 3.8.8，便于 IDE/CI 做类型检查。
- `Client/assets/scripts/ClientConfig.ts` 集中管理 API 地址和客户端业务版本，业务脚本不再直接硬编码 API URL。
- 需要使用 Cocos Dashboard 的 **Creator 3.8.8** 打开 `Client`；不要以项目业务版本号替代 Creator 编辑器版本号。
