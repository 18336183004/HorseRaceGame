# RaceGame 项目规范、编码约定与修改限制

> 适用范围：本仓库中的服务端、客户端、数据库、部署配置与文档。  
> 基线版本：RaceGame V2.0（2026-09-10）。  
> 本文定义后续新增和修改代码应遵循的标准；现存代码若与本文不一致，视为待逐步治理的技术债，不应继续复制。

## 1. 项目定位与技术基线

RaceGame 是一个固定 6 匹马参与的赛马下注游戏工程骨架。

- 服务端：.NET 10、ASP.NET Core 10、EF Core 10、SignalR
- 数据库：PostgreSQL 16
- 缓存与分布式能力：Redis 7、StackExchange.Redis
- 客户端：Cocos Creator 3.8.x、TypeScript
- 本地依赖编排：Docker Compose
- 解决方案入口：`RaceGame.sln`

未经专项升级与完整验证，不得擅自更改上述主版本。

## 2. 目录职责

| 路径 | 职责 | 限制 |
| --- | --- | --- |
| `Server/RaceGame.Domain` | 实体、值对象、枚举、领域规则 | 不依赖 EF Core、Redis、ASP.NET Core 或客户端类型 |
| `Server/RaceGame.Application` | 用例、业务编排、输入输出模型 | 优先依赖领域层和抽象接口，不应新增对 Web 层的依赖 |
| `Server/RaceGame.Infrastructure` | EF Core、PostgreSQL、Redis 等实现 | 不承载 HTTP 接口或客户端表现逻辑 |
| `Server/RaceGame.Worker` | 轮次状态推进和后台任务 | 不实现控制器；任务必须支持取消、幂等与多实例安全 |
| `Server/RaceGame.Api` | HTTP、SignalR、依赖注入、应用启动 | 控制器保持轻量，不直接堆叠核心业务规则 |
| `Client/assets/scripts` | Cocos 客户端组件、API 访问、DTO | 不实现服务端权威结算规则，不信任本地结果 |
| `Database/DeployInit` | 可审计的数据库初始化与升级脚本 | 包含 001~007 脚本，作为数据库结构与种子的唯一定义源 |
| `deploy` | 本地或部署编排 | 不提交真实密码、令牌和生产连接串 |
| `Docs` | 架构、启动、客户端与工程规范 | 行为、接口或运维方式改变时同步更新 |

### 2.1 依赖方向

目标依赖方向为：

```text
Domain <- Application <- Api/Worker
Domain <- Infrastructure <- Api/Worker
```

Application 需要数据库或缓存能力时，应在 Application 或 Domain 定义抽象，由 Infrastructure 实现。禁止形成项目循环引用。

当前 Application 持久化访问已通过 `IGameDbContext` 抽象隔离，Infrastructure 实现该边界；后续应继续把 EF 查询逐步收窄为业务仓储/工作单元接口，避免新的应用层基础设施耦合。

## 3. 通用编码原则

1. 新代码必须可读、可格式化，禁止沿用现有部分文件的“整文件单行压缩”写法。
2. 一个文件通常只定义一个主要公开类型；文件名与主要类型名一致。
3. 优先修复根因，避免在控制器、Worker 或客户端重复业务判断。
4. 保持改动最小且聚焦，不借任务之机重命名无关符号或重构无关模块。
5. 公共行为、协议和持久化结构变更必须补充测试与文档。
6. 不吞掉异常；记录足够上下文，但不得记录密码、令牌、完整连接串或隐私数据。
7. 注释解释约束、原因和取舍，不复述代码。
8. 所有文本文件使用 UTF-8，默认 LF；提交前使用对应工具格式化。

## 4. C# / .NET 规范

### 4.1 格式与命名

- 使用 4 空格缩进、文件作用域命名空间和启用的 Nullable 引用类型。
- 类型、公开成员、枚举值使用 `PascalCase`。
- 参数、局部变量、私有字段使用 `camelCase`；私有只读字段可使用 `_camelCase`。
- 异步方法以 `Async` 结尾，并返回 `Task`/`Task<T>`；除事件处理外禁止 `async void`。
- 避免无意义的单字母命名。循环索引可使用 `i`，上下文非常明确时可使用短名称。
- `using`、特性、成员和语句各自换行；类型和方法体不得压成一行。
- 优先使用构造函数注入；禁止服务定位器式地在业务代码中任意解析依赖。

### 4.2 异步与取消

- 控制器、EF Core 查询、后台任务和外部 I/O 应接收并传递 `CancellationToken`。
- 禁止用 `.Result`、`.Wait()` 阻塞异步调用。
- Worker 的循环必须响应取消；取消导致的 `OperationCanceledException` 不应作为普通错误记录。
- 后台异常使用 `ILogger<T>` 结构化记录，禁止新增 `Console.WriteLine`。

### 4.3 API

- 路由保持小写、资源导向，并维持现有 `/api/...` 前缀。
- 请求与响应使用明确 DTO，不直接把 EF 实体作为长期 API 合约。
- 当前成功响应采用 `{ code: 0, data: ... }`，业务失败采用非零 `code` 与 `message`；修改该格式属于破坏性变更。
- 使用统一异常映射处理可预期业务错误；不得在每个控制器重复捕获所有 `Exception` 并泄漏内部异常文本。
- 参数必须在服务端校验。客户端校验只能改善体验，不能替代服务端校验。
- HTTP 状态码应与结果匹配：参数/业务冲突、未认证、无权限、未找到和服务端错误不可全部返回 200。

### 4.4 领域与持久化

- 时间统一使用 UTC；持久化使用 `TIMESTAMPTZ`。禁止用本地时间参与轮次判断。
- 金额、赔率和奖励使用 `decimal`/PostgreSQL `NUMERIC`，禁止使用 `float` 或 `double` 表示金钱。
- 钱包余额变更必须处于数据库事务中，同时写入 `wallet_transactions` 审计流水。
- 下注、奖励和可重试命令必须具备数据库唯一约束支持的幂等键；不能只依赖“先查再写”。
- 钱包并发修改必须使用可靠的乐观并发令牌、原子 SQL 或行锁。仅递增 `Version` 而未配置并发令牌不视为完成并发控制。
- 状态转换必须显式、单向且可验证。不得绕过 `RaceState` 随意赋值。
- `RaceState` 的整数值已进入数据库协议，禁止重排或复用；新增状态只能追加并配套迁移与兼容评估。
- 服务端是比赛结果、赔率、钱包和结算的唯一权威来源。

## 5. TypeScript / Cocos 规范

- 使用 4 空格缩进、分号和清晰换行；类/接口使用 `PascalCase`，变量/函数使用 `camelCase`。
- 禁止新增 `any`；API 数据先通过明确 DTO 或运行时校验后再使用。
- API 地址不得继续硬编码在业务类中，应从环境或集中配置读取。
- 网络调用必须处理超时、取消、错误和非预期响应；用户可见操作应避免无提示失败。
- Cocos 组件公开给编辑器的字段使用 `@property`，访问前处理可能为 `null` 的节点引用。
- 组件销毁时清理计时器、事件监听和网络订阅。
- 不在每帧 `update` 中发起网络请求或创建大量临时对象。
- 场景节点路径以 `Docs/08_Client/SCENE_NODE_STRUCTURE.md` 为兼容基线。修改节点名或层级时同步修改脚本绑定和文档。
- 客户端动画可插值展示，但不得自行决定最终名次、奖励或余额。

## 6. 数据库与迁移规范

- 表名、列名、索引名使用 `snake_case`；C# 使用 `PascalCase`，映射应明确且稳定。
- 新迁移按递增编号命名，例如 `002_add_wallet_concurrency.sql`。
- 不修改已经共享或部署的 `001_initial.sql`；需要修正时创建后续迁移。
- 破坏性 DDL 必须给出备份、数据迁移、回滚与停机影响说明。
- 外键、唯一约束、金额精度、非空和默认值应由数据库兜底，不能只靠应用层。
- EF Core 模型与 SQL 迁移必须保持一致；自动迁移用于本地开发，生产环境应使用受控迁移流程。

## 7. 安全与配置限制

以下现状仅适用于开发骨架，不得作为生产实现继续扩散：

- `dev-login` 没有正式认证流程。
- 下注接口当前硬编码 `playerId = 1`。
- CORS 当前允许任意来源、请求头和方法。
- Swagger 当前无环境限制。
- 数据库账号密码和客户端 API 地址为本地硬编码值。
- Worker 尚未使用 Redis 分布式锁，多实例运行可能重复推进轮次。
- Redis 锁接口尚无安全释放实现。
- SignalR Hub 已存在，但状态广播尚未完成。
- 赛果随机种子依赖 `string.GetHashCode()`，跨进程/运行时不保证稳定，不满足可复核的确定性要求。
- 日志、审计、严格钱包并发控制和完整测试尚未完成。

因此：

1. 不得声称当前项目“生产可用”“资金安全”或“公平性已审计”。
2. 不得提交真实密钥、令牌、生产密码或个人数据。
3. 敏感配置使用环境变量、用户机密或密钥管理服务；仓库只保留安全示例。
4. 正式认证完成前，不得把 `dev-login` 暴露到公网环境。
5. 正式部署前必须收紧 CORS、Swagger、错误详情、数据库权限和网络暴露。

## 8. 核心业务不变量

除非需求明确改变且完成全链路评审，否则必须保持：

- 每轮固定 6 匹马，马号范围为 1–6。
- 每位玩家每轮只能选择一匹马。
- 下注仅在 `Betting` 状态且截止时间前接受。
- 余额不足或下注金额不大于 0 时拒绝下注。
- 下注时锁定赔率；结算使用订单的 `LockedOdds`/`PotentialReward`，不得使用后续变化的赔率。
- 一笔幂等请求最多产生一个订单和一次钱包扣款/奖励。
- 无下注轮次可跳过比赛；有下注轮次按下注、准备、比赛、结算、完成的顺序推进。
- 比赛结束后才能结算，已完成轮次不得重复结算。

## 9. 测试与验证

新增行为至少覆盖与改动匹配的测试层级：

- Domain/Application：状态转换、金额计算、下注规则、幂等和异常路径的单元测试。
- Infrastructure：PostgreSQL 唯一约束、事务、并发与 Redis 锁的集成测试。
- Api：状态码、响应结构、认证授权和参数校验测试。
- Worker：时间边界、重复执行、多实例竞争、取消和恢复测试。
- Client：DTO 解析、倒计时边界、错误处理与组件生命周期测试。

提交前按改动范围执行：

```bash
dotnet restore Server/RaceGame.Api/RaceGame.Api.csproj
dotnet build Server/RaceGame.Api/RaceGame.Api.csproj --configuration Release
# 修复解决方案项目映射后，再增加 RaceGame.sln 级构建。
# 存在测试项目后：
dotnet test RaceGame.sln --configuration Release --no-build
```

客户端补齐 Cocos 工程元数据和脚本后，使用 Cocos Creator 3.8.x 完成场景加载、脚本编译和节点绑定验证。

## 10. 文档与完成定义

一项改动完成时应满足：

- 架构依赖和核心业务不变量未被破坏。
- 新代码已格式化，无新增编译错误和相关诊断。
- 成功、失败、边界、重试或并发路径已按风险覆盖。
- 数据库、API、配置或场景结构变更已同步文档。
- 没有引入秘密、调试后门、硬编码玩家身份或生产不安全默认值。
- 明确记录实际执行的验证命令；未能验证时说明原因。

## 11. 当前基线的已知缺口

截至本文建立时：

- 仓库没有测试项目、`.editorconfig`、TypeScript 工程配置和完整 Cocos 工程元数据。
- 多个 C# 与 TypeScript 文件采用单行压缩格式，后续触达时应在不扩大功能改动的前提下格式化相关文件。
- `RaceGame.sln` 缺少 `ProjectConfigurationPlatforms` 项目映射；当前解决方案级命令可能未编译任何项目却返回成功，不能作为有效验证结果。
- EF 自动迁移与独立 SQL 初始迁移并存，尚未明确单一迁移来源。
- 认证、授权、广播、分布式锁、并发、可复核随机算法、审计和生产配置仍属于未完成功能。

处理这些缺口应拆分为可审查任务，不得在无测试保护时一次性大范围重写。

## 12. V2.0 发布增量约束

- 当前业务版本基线为 V2.0.0；Cocos Creator 固定 3.8.8。
- 现金充值、提现、USDT、链上钱包、玩家金币转赠、第三方邀请链接不是当前产品能力；客户端不得出现可操作的假入口。
- 下注和商城订单的幂等键必须与请求参数指纹绑定；同键不同参数必须拒绝。
- 登录失败达到 5 次后临时锁定 10 分钟；玩家可通过 Logout 撤销当前 Refresh Token 会话。
- 大厅近期赛果必须来自服务端 `/api/race/history`，禁止硬编码历史结果。
- 生产 Docker 初始化使用 `Database/DeployInit`，其中不包含开发测试玩家和固定管理员密码。
- 历史 V1.x 文档只作为变更记录；发生冲突时 V2.0 产品、架构、数据、API、QA 文档优先。
